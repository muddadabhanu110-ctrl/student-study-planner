## 7. Functional Requirements

Functional requirements describe the features that the system must provide.

### FR-01: User Registration

The system shall allow a new user to create an account using basic information such as name, email, and password.

### FR-02: User Login

The system shall allow registered users to log in using their credentials.

### FR-03: Subject Management

The user shall be able to:

- Add a subject.
- View subjects.
- Edit a subject.
- Delete a subject.

### FR-04: Study Task Creation

The user shall be able to create a study task by entering information such as:

- Task title.
- Subject.
- Description.
- Deadline.
- Priority.

### FR-05: Task Management

The user shall be able to:

- View tasks.
- Edit tasks.
- Delete tasks.
- Update task status.

### FR-06: Task Completion

The system shall allow users to mark a task as completed.

### FR-07: Pending Tasks

The system shall display tasks that have not yet been completed.

### FR-08: Completed Tasks

The system shall display completed study tasks separately from pending tasks.

### FR-09: Progress Tracking

The system shall calculate and display basic study progress based on completed and pending tasks.

### FR-10: Dashboard

The system shall provide a dashboard containing useful information such as:

- Total subjects.
- Total tasks.
- Pending tasks.
- Completed tasks.
- Overall progress.

### FR-11: Logout

The system shall allow users to securely log out of their account.

## 8. Non-Functional Requirements

### 8.1 Usability

- The interface should be simple and easy to understand.
- Navigation should be clear.
- Important actions should be easily accessible.

### 8.2 Performance

- The system should respond to normal user actions within a reasonable time.
- Database operations should be efficient for the expected number of users.

### 8.3 Security

- User authentication should be implemented.
- Passwords should not be stored as plain text.
- Users should only be able to access their own study information.

### 8.4 Reliability

- The system should correctly save user data.
- The application should handle invalid input without crashing.

### 8.5 Maintainability

- The source code should be organized into appropriate modules.
- Clear naming conventions should be followed.
- Comments and documentation should be provided where necessary.

### 8.6 Compatibility

The application should work on commonly used modern web browsers.
